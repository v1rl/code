## F MEX 贡献拆分与前缀链的摊还维护

**题目极简总结**

**题意**：给定一棵 $N$ 个节点的无根树，节点编号为 0 到 $N-1$。对于任意一对节点 $(i, j)$，定义 $f(i, j)$ 为从 $i$ 到 $j$ 的简单路径上**未出现的最小非负整数**（即 MEX）。

**目标**：求所有无序节点对 $(i, j)$ 的 $f(i, j)$ 之和。

**思路 Trick (Key Observations)**

求所有路径的 MEX 之和，如果正面硬刚去枚举路径求 MEX，复杂度必然爆炸。这里有两个堪称经典的 ICPC 核心思维跳跃：

1. **贡献拆分 (Sum of MEX = Count of Prefixes)**
   - **痛点**：MEX 的值域是 $0 \sim N$，每次算出一个具体的数很难进行批量统计。
   - **跳跃**：在组合数学和期望问题中有一个经典等式：对于非负整数变量 $X$，有 $\sum X = \sum_{k=1}^{\infty} [X \ge k]$。
   - **结论**：我们要让某条路径的 MEX 大于等于 $k$，**充要条件是这条路径必须同时包含 0, 1, 2, ..., k-1**。因此，原问题完美转化为：求有多少条路径包含了前缀集合 `{0}`，加上包含了 `{0, 1}` 的路径数，一直加到包含了 `{0, 1, ..., N-1}` 的路径数！
2. **前缀链的拓扑约束 (Prefix Chain)**
   - **痛点**：怎么快速判断树上存不存在一条路径同时包含 0 到 $k-1$？
   - **跳跃**：跟上一题类似，要让一条简单路径穿过这么多指定的点，这些点**必须自己就能连成一条简单路径（链）**。
   - 我们可以维护包含 $0 \sim k-1$ 的那条链的两个端点 $L$ 和 $R$（初始时 $L=R=0$）。当我们要加入节点 $k$ 时：
     - 它要么已经在 $L$ 到 $R$ 的路径上（无事发生）。
     - 它要么在 $L$ 的外侧（更新 $L=k$），或者在 $R$ 的外侧（更新 $R=k$）。
     - 如果它在链的中间岔出去了（即它的投影不在 $L$ 也不在 $R$），说明**前缀链彻底断裂**，后续的 $k+1, k+2$ 再也不可能满足，直接 `break` 结束全剧。

**编码 Trick (Coding Elegance)**

你的代码中有两处极其出彩的“工程化”处理，把树上路径问题化简到了极致：

1. **树上单向游标与摊还分析 (Amortized Climbing)**

   ```cpp
   while(x >= 1 && !vis[x]) {
       vis[x] = true;
       // ...
       x = p[x];
   }
   ```

   判断 $k$ 在不在 $L$ 或 $R$ 的延长线上，传统的笨办法是疯狂求 LCA 算距离。而你的做法是：直接顺着父指针往上爬，直到碰到已经在这条链上（`vis[x] == true`）的节点为止。

   因为每个节点最多被标记一次，全过程这个 `while` 循环的总执行次数严格等于 $N$！这是极度优雅的 $O(N)$ 摊还处理。

2. **以 0 为根的子树乘法原理 (`v0` 的妙用)**

   整棵树以 0 为根，极大地方便了统计“有多少条路径经过这条链”：

   - 当链跨过 0，一端是 $L$，另一端是 $R$ 时，合法的终点分别在它们的子树里，路径数就是 `siz[l] * siz[r]`。
   - **特殊边界**：当 $L=0$ 时（链还没跨过 0，只在 0 的一侧延伸），一端在 $R$ 的子树里（`siz[r]`），另一端可以在**除 $R$ 所在分支外的任意节点**。你极其巧妙地在向上爬的时候记录了进入 0 的那个儿子 `v0`，从而用 `siz[l] - siz[v0]`（也就是 `N - siz[v0]`）瞬间得出了另一端的合法数量。免去了复杂的换根 DP。

**逻辑链条 (The Logic Chain)**

1. **等价转化**：将“求所有路径的 MEX 和”转化为“求分别包含前缀节点集 $\{0, \dots, k-1\}$ 的路径数量之和”。
2. **初始化根基**：以 0 为树根跑 DFS，求出所有节点的子树大小 `siz` 和父节点 `p`。
3. **计算基底 (k=1)**：初始链端点为 $L=0, R=0$，通过子树乘法求出所有经过 0 的路径数量，计入答案。
4. **增量维护链 (k>1)**：从小到大枚举 $k$，若 $k$ 未被访问，沿父节点向上爬进行染色，直到撞到已染色的链。
5. **判定与断裂**：如果撞到的节点恰好是 $L$ 或 $R$，则将对应的端点更新为 $k$；若撞到了链的中间，说明前缀链无法保持简单路径，直接 `break`。
6. **组合计数**：端点更新后，根据 $L$ 和 $R$ 是否包含 0，利用 `siz` 数组和 `v0` （0 的第一层儿子）快速算出当前链的覆盖路径数，累加至总答案。



## F 基于 LCA 与距离方程的前缀链拓展

**题目极简总结**

**题意**：给定 $N$ 个节点的无根树，求所有无序节点对 $(i, j)$ 的简单路径 MEX 之和。

**转化**：求有多少条路径包含了前缀集合 `{0}`，加上包含了 `{0, 1}` 的路径数，一直加到包含了 `{0, 1, ..., N-1}` 的路径数。

**思路 Trick (Key Observations)**

上一份代码的局限性在于：必须把树根强制设为节点 0，利用祖先-后代关系去模拟链的延伸。

而这份代码的跳跃点在于：**放弃祖先-后代的强绑定，利用纯粹的“距离方程”来定义树上路径**。

1. **树上距离方程 (Geometric Path Check)**

   - **痛点**：任意指定一个根，链的形态可能是一条折线（跨越 LCA）。怎么判断点 $z$ 是否在折线 $x-y$ 上？

   - **跳跃**：在树这种绝对的最短路图中，点 $z$ 在 $x$ 到 $y$ 的简单路径上，**当且仅当**满足距离方程：

     $$dist(x, z) + dist(y, z) == dist(x, y)$$

   - 这直接降维打击了所有的繁琐特判，把复杂的拓扑关系变成了一行代数等式！

2. **端点拓展的三向判定 (Tri-directional Extension)**

   有了上面的距离方程，判断新节点 $z$ 如何加入端点为 $x, y$ 的链，变得如同在一条直线上做解析几何一样清晰：

   - $z$ 已经被包在里面了：$z$ 满足在 $x-y$ 之间（无事发生）。
   - $z$ 在 $x$ 的外侧：$x$ 满足在 $y-z$ 之间，此时链拉长，新端点变成 $z$ 和 $y$。
   - $z$ 在 $y$ 的外侧：$y$ 满足在 $x-z$ 之间，此时链拉长，新端点变成 $x$ 和 $z$。
   - 都不满足：前缀链彻底断裂。

3. **垂直链的容斥计数 (Subtree Exclusion)**

   在统计经过 $x-y$ 链的路径数时，根据 LCA 的位置分为两类：

   - **折线链**（$x, y$ 分别在 LCA 的两个分支）：两端互不干扰，合法路径数直接是 $siz[x] \times siz[y]$。
   - **垂直链**（$x$ 是 $y$ 的祖先，即 `p == x`）：一端在 $y$ 的子树里（$siz[y]$），另一端必须在**除了走向 $y$ 的那个分支以外的所有节点中**。这就引出了极为关键的 `jump(y, x)` 操作——找到 $x$ 的所有儿子中，指向 $y$ 的那一个，用总节点数 $N$ 减去它的 $siz$ 即可。

**编码 Trick (Coding Elegance)**

这份代码的“工程化抽象”做得极好，完全可以作为你树上倍增的万能模板：

1. **黑盒化树上几何运算 (Encapsulation)**

   ```cpp
   auto lca = [&](int x, int y) -> int { ... };
   auto dist = [&](int x, int y) -> int { return dep[x] + dep[y] - 2 * dep[lca(x, y)]; };
   auto on = [&](int x, int y, int z) { return dist(x, z) + dist(y, z) == dist(x, y); };
   auto jump = [&](int x, int y) -> int { ... };
   ```

   你将 `lca`, `dist`, `on` (三点共线), `jump` (树上 K 步跳跃) 全部封装成了 Lambda 表达式。在主逻辑 `for(int i = 1; i < n; i++)` 中，代码读起来就像是用人类自然语言在描述数学定理一样流畅。这种模块化思维能让你在几百行的大模拟、大图论题中**绝对不会被细节绕晕**。

2. **巧妙的二进制起跳 (`jump` 函数)**

   ```cpp
   for(int i = 19; i >= 0; i --) {
       if(dep[f[x][i]] >= dep[y] + 1) x = f[x][i];
   }
   ```

   要找 $x$ 走向 $y$ 路径上的第一个点（已知 $y$ 是 $x$ 的祖先），不需要从 $y$ 往下搜，而是直接让 $x$ 往上跳，跳到深度恰好是 $dep[y] + 1$ 的位置。短短 4 行代码搞定了树上最恶心的“查找指定路径分支”问题。

**逻辑链条 (The Logic Chain)**

1. **倍增预处理**：以任意点（此处为 0）为根，BFS 或 DFS 预处理出 `dep`, `siz`, 及 $2^i$ 级祖先数组 `f`。
2. **基底计算**：初始化链端点为 $x=0, y=0$。利用乘法原理单独计算路径经过节点 0 的组合数（在 0 的各子树之间两两组合）。
3. **几何验证**：从小到大枚举 $k = 1 \dots N-1$，调用 `on` 函数利用距离方程判定 $k$ 是已被包含、向 $x$ 端拓展、向 $y$ 端拓展、还是导致链断裂。
4. **形态分类**：通过 `lca(x, y)` 判断当前链的形态。
5. **子树求交**：若是折线链，累加 `siz[x] * siz[y]`；若是垂直链，利用 `jump` 排除掉向内生长的分支，用剩余全局节点数乘以较深端的 `siz`，累加至答案。

**两种解法巅峰对决总结**

- **前一份代码（摊还 DFS 游标）**：
  - **优点**：时间复杂度严格 $O(N)$，常数极小，不需要写 LCA，代码短。
  - **代价**：极度依赖“以 0 为根”这个特定视角的巧思，思维跳跃度大。
- **本份代码（LCA 距离几何）**：
  - **优点**：思维极度通用，不仅能解决 0 为起点，还能随时处理任意区间的 MEX。它抽象出了树上路径的几何本质，可以无缝套用到其他任何复杂的树上路径问题中。
  - **代价**：多了预处理 LCA 的 $O(N \log N)$ 复杂度和倍增的常数。
