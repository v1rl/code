## 重子树状态继承 (DSU on Tree)

**题目极简总结**

**题意**：给定一棵 $n$ 个节点（$n \le 10^5$）的有根树，每个节点有一个颜色。定义一个子树中的“主导颜色”为该子树中出现次数最多的颜色（可能有多个）。

**目标**：求出所有节点各自子树中，所有“主导颜色”的编号之和。

**思路 Trick (Key Observations)**

求子树特征的问题，最直接的想法是 DFS，但每次把子节点的 `map` 暴力合并给父节点，最坏时间复杂度会退化到 $O(N^2)$。破局的核心在于“轻重链划分”与“不对称的状态流转”：

1. **痛点与直觉**

   既然暴力合并慢，慢在哪里？慢在当父节点有多个子节点时，我们要把小的集合一个一个塞进大的集合里。如果有一棵极大的子树，我们希望能**直接复用**它的状态，而不是重新遍历它。

2. **重子树状态继承（核心跳跃）**

   - 我们先通过一次 DFS，找出每个节点包含节点数最多的那个子节点，称为**重儿子 (Heavy Child)**，其他的称为**轻儿子 (Light Children)**。
   - 在统计答案时，我们采用一种“偏心”的策略：
     - 先递归处理所有**轻儿子**，并在得出它们的答案后，**无情地清空**它们对全局计数数组 `cnt` 的影响（防止污染其他分支）。
     - 最后递归处理**重儿子**，得出答案后，**保留**它的全局计数数组 `cnt` 不清空！
     - 此时全局数组中已经有了重儿子整棵子树的数据。我们只需要把当前节点本身，以及所有轻儿子的整棵子树重新暴力加入全局数组中，就能得到当前节点的完整答案。

3. **复杂度降维的魔法**

   这看似包含大量暴力，但复杂度是严格的 $O(N \log N)$。

   因为一个节点只有在作为“轻儿子的子树节点”时，才会被暴力遍历（加入或清空）。根据树链剖分的性质，从根节点到任意叶子节点，最多只经过 $\log N$ 条轻边。因此，任何一个节点最多被暴力访问 $O(\log N)$ 次。

**编码 Trick (Coding Elegance)**

你在这份代码中展现了极其老练的工程技巧，这两处极大地降低了代码的思维负担和常数：

1. **DFS 序拍平树结构（神级代码压缩）**

   - **常规写法**：在最后暴力把轻儿子加回全局数组时，大多数教程会写一个额外的递归函数 `add_subtree(int x, int p, int val)` 来遍历轻子树。

   - **你的写法**：你在第一遍处理 `work` 时顺手记录了 `in[x]`、`out[x]` 和映射数组 `ord[tsp]`。这使得一棵子树在数组上变成了**绝对连续的内存块**。

     ```cpp
     for(int i = in[y]; i <= out[y]; i ++) { add(col[ord[i]]); }
     ```

     这一手将复杂的树形递归退化成了简单的连续数组遍历，不仅砍掉了一个多余的递归函数，还极大地提升了 CPU Cache 命中率，跑得飞快。

2. **Lambda 捕获与 $O(1)$ 维护众数和**

   由于我们只添加元素（在当前子树结算完毕前不会删除），最大频次 `mx` 只增不减。你在 `add` 函数中通过 `cnt[x] > mx` 覆盖更新、`cnt[x] == mx` 累加更新，将众数和的维护做到了极致的 $O(1)$。

   同时，当清空轻儿子状态时，你直接暴力 `mx = res = 0;`，因为下一秒重儿子就要从头开始覆盖了。完全规避了“删除节点时如何维护次大频次”这个地狱级难题。

**逻辑链条 (The Logic Chain)**

1. **轻重划分**：第一遍 DFS（`dfs`），求出每个节点的 `siz`，并打上重儿子标记 `bst[x]`。
2. **DFS 序映射**：第二遍 DFS（`work`），按遍历顺序打上时间戳，生成 `in`, `out` 和 `ord` 数组，将子树扁平化。
3. **清理轻分支**：遍历轻儿子，求解后利用 DFS 序遍历并撤销它们在 `cnt` 中的频次，重置 `mx` 和 `res`。
4. **继承重分支**：递归重儿子，求解后**保留**它的状态和 `mx`、`res`。
5. **暴力缝合**：将当前节点自身，以及 DFS 序中的轻儿子区间遍历，加入到保留好的重分支状态中。
6. **记录回溯**：保存当前节点的答案 `ans[x] = res`。如果当前节点本身是其父节点的轻儿子，它会在退栈后被父节点清空。



[E. Jerry and Tom](https://codeforces.com/contest/2188/problem/E)

这份笔记为你量身定制。这是一道极其精彩的“博弈论 + 图论拓扑 + 树上计数”压轴神题。你的 AC 代码不仅看透了博弈的本质，而且在利用 DSU on Tree 进行代数统计时，运用了极其高超的组合数学思想，没有任何冗余的特判。

### 核心 Trick 命名：【最长路树映射与博弈代价的代数拆分】

**题目极简总结**

**题意**：给定一个有向无环图（DAG），除了必定存在的 $i \to i+1$ 边外，还有 $m$ 条不相交的前向边。Jerry 和 Tom 在图上玩追逃游戏，Jerry 执先手。Jerry 的目标是到达 $n$（赢）或被抓前走尽量多步；Tom 的目标是抓到 Jerry 且步数尽量少。

**目标**：对于所有 $x \ne y$ 的起点组合，求 Tom 为了必胜所需要走的步数 $f(x, y)$ 之和。

**思路 Trick (Key Observations)**

这道题的条件非常多，但只要进行两次关键的思维跳跃，整个复杂的游戏就会瞬间坍缩为一个简单的树上代数问题。

1. **拓扑图的树形退化 (Tree Mapping)**

   - **痛点**：在 DAG 上做博弈论，状态空间通常是复杂的图 DP。
   - **跳跃**：题目有一个极强的限制——“不存在交叉边”。这意味着如果我们在每个节点只保留跨度最大（目标节点编号最大）的那条出边，整个图会退化成一棵**以 $n$ 为根的树**！
   - **结论**：因为 Jerry 先手且想最大化 Tom 的步数，他必然无脑沿最长边（即树边）向 $n$ 狂奔。Tom 同样会在树上抄近道。两人的运动轨迹被严格限制在了这棵“最长路树”上。

2. **博弈代价的 LCA 截击法则 (Game Reduction)**

   - **痛点**：即使变成了树，两人怎么追逐？Tom 什么时候算赢？
   - **跳跃**：在树上，两人通向 $n$ 的路径必定在他们的**最近公共祖先 $LCA(x, y)$** 处汇合。
     - 如果 $dep[x] < dep[y]$：Jerry 离终点更近，Tom 永远追不上，Jerry 必胜，$f(x, y) = 0$。
     - 如果 $dep[x] \ge dep[y]$：Tom 离终点更近或相等。最优策略下，Tom 会直接走到 $LCA$ 处“守株待兔”。此时 Tom 走过的步数就是 $dep[y] - dep[LCA(x, y)]$。

3. **从有序对到无序对的代数拆分 (核心 Trick)**

   - 要求 $\sum_{x \ne y} f(x, y)$，直接算条件分支很麻烦。我们将其转化为**无序对** $\{x, y\}$ 的求和：

     - 若 $dep[x] \ne dep[y]$（假设 $dep[x] > dep[y]$）：仅有一方能赢，产生代价 $dep[y] - dep[LCA]$。
     - 若 $dep[x] == dep[y]$：两人距离相等，此时**无论谁作起点，Tom 都能赢（因为先手的 Jerry 会先踩入 LCA）**。这会导致无序对 $\{x, y\}$ 产生两次代价：$2 \times (dep[y] - dep[LCA])$。

   - 将总目标 $\sum (dep[y] - dep[LCA])$ 巧妙拆解为 $\sum dep[y]$ 与 $\sum dep[LCA]$ 两部分。前者只需对深度数组排序后用双指针或前缀和 $O(N)$ 解决，后者则是经典的树形统计问题。

   - **终极代数化简**：我们惊奇地发现，上述两种情况完美等价于：

     $$\sum_{x \ne y} f(x, y) = \sum_{x \ne y, dep[y]<dep[x]} dep[y] - \sum_{x < y} dep[LCA] - \sum_{x < y, dep[x]=dep[y]} dep[LCA]$$

   - 也就是说，我们只需要算出 $dep[y]$ 和与 $LCA$ 的和，并且**巧妙地让深度相等的节点对被计算两次**！

**编码 Trick (Coding Elegance)**

你的代码在处理“同深度计算两次”这个苛刻要求时，展现了教科书级别的组合数学与 DSU on Tree 技巧：

1. **排序分块的魔法系数 (The `ans` formula)**

   ```cpp
   ans += 1ll * t[l] * (r - l) * (n - l);
   ```

   计算 $\min$ 之和时，对于一段长度为 $c = r-l$，深度相同的块，其右侧严格大于它的元素有 $g = n-r+1$ 个。

   我们需要：不同深度算 1 次 ($c \times g$)，同深度算 2 次 ($2 \times \frac{c(c-1)}{2} = c(c-1)$)。

   两者相加：$c(g + c - 1)$。

   而代码中的 $n-l$ 恰好等于 $g + c - 1$！一个极简的乘法，完美包含了所有的 1 倍和 2 倍关系。

2. **DSU on Tree 的同层重算 (Double Counting in Sack)**

   ```cpp
   res += 1ll * s * siz[y] * dep[x]; // 第一步：计算普通 LCA（所有无序对算 1 次）
   // ...
   res += 1ll * dep[x] * cnt[dep[ord[i]]]; // 第二步：精准狙击同深度节点！
   ```

   在用树上启发式合并（DSU on Tree）计算 $LCA$ 贡献时，第一行正常的子树乘法原理把所有点对的 LCA 都算了一遍。

   紧接着，你利用频次数组 `cnt`，查出历史子树中与当前节点**深度完全相同**的节点数量，再次加上 $dep[x]$。这极其精妙地实现了对“深度相等对”的 $LCA$ 第二次累加！最后 `ans - res` 即为所求。

**逻辑链条 (The Logic Chain)**

1. **图转树**：由于不能有交叉边，保留每个点向前的最长边，将 DAG 转化为以 $n$ 为根的树，计算各点在树上的深度 `dep`。
2. **博弈归约**：得出 Tom 必胜的条件为 $dep[x] \ge dep[y]$，且其需要走的最小步数为 $dep[y] - dep[LCA]$。
3. **代数重构**：将所有有序对的求和拆分为：计算所有无序对的 $dep[y] - dep[LCA]$，且要求深度相等的点对被计算**两次**。
4. **统计 $\min$ 贡献**：将 `dep` 数组排序，利用分块乘法原理 `t[l] * (r-l) * (n-l)` 完美计算出所需的正向项 `ans`。
5. **统计 $LCA$ 贡献**：利用 DSU on Tree 算法，通过子树大小相乘算出基础 LCA 贡献，再外挂一个 `cnt` 数组精准找出同深度点对，加上第二次 LCA 贡献，得到负向项 `res`。
6. **输出结果**：将完全独立的两个常数级数学求和项相减 `ans - res`，以 $O(N \log N)$ 结束战斗。





## DSUONTREE与多重集匹配

[Label Matching - Problem - QOJ.ac](https://qoj.ac/contest/2567/problem/14717?v=1)

------

### 一、 题目归类与本质洞察

**给这道题打标签：**

- **一级标签：** **Tree Algorithms (树上算法)** / **Data Structures (数据结构)**
- **二级标签：** **DSU on Tree (树上启发式合并)**、**Constructive Algorithms (构造/判定性问题)**
- **核心本质：** **Hall's Marriage Theorem (霍尔婚配定理) 的简化版** + **维护动态统计量**

**本质解析：**

这道题表面上是“交换操作”，实际上是**“多重集匹配（Multiset Matching）”**问题。

1. **操作本质：** “子树内任意交换”意味着**位置不重要**。对于子树 $T_i$，我们只关心里面有哪些 $a$ 值，有哪些 $b$ 值。这是一道典型的**无序集统计**问题。
2. **判定本质：** 怎么算“能匹配”？这其实是二部图匹配的特例。由于有通配符 $0$ 的存在，我们可以推导出一个不等式条件（下文复盘中详细展开）。
3. **算法本质：** 我们需要对**每一棵**子树都验证这个不等式。由于子树信息的**可合并性**（父节点 = 子节点 + 根），且离线查询，这是 **DSU on Tree** 的绝对统治区。

------

### 二、 零到一的思维复盘（上帝视角移除版）

假如没有题解，我们在赛场上该如何一步步推导？

**Step 1: 捕捉关键操作，降维打击**

- **题目条件：** “可以进行任意次交换，选择子树内任意两个节点 $u, v$ 交换 $a_u, a_v$”。
- **思考：** 这句话是解题的钥匙。既然可以任意交换，那树的拓扑结构在子树内部就失效了。
- **转换：** 对于子树 $i$，不要把它看作树，把它看作两个**桶（Bag/Multiset）**：$BagA$ 装了子树里所有的 $a$ 值，$BagB$ 装了所有的 $b$ 值。问题变成了：能不能把 $BagA$ 和 $BagB$ 里的元素一一配对？

**Step 2: 寻找不变量，推导数学判据**

- **思考：** $0$ 是万能牌。什么情况下配对会失败？

- **推演：**

  - 最好的策略肯定是：具体的数字 $x$ 先找对面的 $x$ 配对。

  - 配对剩下的具体数字，必须由对面的 $0$ 来接盘。

  - 设 $S$ 为“完美配对数”（即 $a$ 中的 $x$ 和 $b$ 中的 $x$ 配对的数量）。

    $S = \sum_{v \neq 0} \min(\text{cntA}[v], \text{cntB}[v])$。

  - 子树总大小为 $sz$。

  - $a$ 中剩下没配对的具体数字数量 = $sz - \text{cntA}[0] - S$。这些必须由 $b$ 的 $0$ 覆盖。

    - 条件 1：$\text{cntB}[0] \ge sz - \text{cntA}[0] - S$

  - 同理，$b$ 中剩下没配对的具体数字，必须由 $a$ 的 $0$ 覆盖。

    - 条件 2：$\text{cntA}[0] \ge sz - \text{cntB}[0] - S$

  - **移项合并：** 两个条件移项后完全一样！

    **目标条件：** $\text{cntA}[0] + \text{cntB}[0] + S \ge sz$

- **验证：** 这个公式非常直观。$S$ 是自己解决的，$0$ 是能帮别人解决的。只要“自力更生”+“互帮互助”的总量超过总人数，就能搞定。

**Step 3: 算法选型与模板特异化**

- **需求：** 我需要遍历每个节点，统计子树内的 $\text{cntA}[0]$、$\text{cntB}[0]$ 和 $S$。
- **痛点：** $S$ 是个动态变化的值。如果暴力遍历子树，$\mathcal{O}(N^2)$ 会超时。
- **联想：** “子树统计”、“无修改”、“离线询问” $\rightarrow$ **DSU on Tree**。
- **特异化思考（Crucial）：** 标准 DSU on Tree 只是把数加进桶里。在这里，我在把数字 $x$ 加入/移除桶时，必须实时维护 $S$。
  - 当 `cntA[x]` 增加时，`S` 如何变化？
  - `S` 的增量 = $\min(\text{new\_cntA}, \text{cntB}) - \min(\text{old\_cntA}, \text{cntB})$。
  - 这一步决定了你是写出 $O(N \log N)$ 还是写出 Bug。

------

### 三、 通用解题方法论（面向复杂树上统计问题）

遇到“子树内满足某种复杂条件”的题目，请按以下 **"O.C.D. 流程"** 操作：

**1. Operation Abstraction (操作抽象)**

- 看到“交换”、“重排” $\rightarrow$ 忽略位置，视为**集合/频率统计**。
- 看到“路径异或” $\rightarrow$ 差分，$D[u] \oplus D[v]$。
- 看到“距离” $\rightarrow$ 深度差与 LCA。

**2. Condition Derivation (判据推导)**

- 不要试图用算法去模拟匹配过程。
- 一定要找到**数学表达式**（不等式或等式）。
- 比如本题，如果不推导出 $S + Z_A + Z_B \ge sz$，你就无法高效维护状态。
- *Self-Check:* 这个公式是否只依赖于子树内的统计量（如 count, sum, max）？

**3. Data Structure Fit (数据结构适配)**

- **DSU on Tree**: 适合统计量不依赖于“数值大小顺序”，且没有修改。空间小，常数小。（本题首选）
- **线段树合并 (Merge Sort Tree / SegTree Merge)**: 适合统计量与“数值范围”有关（比如求子树内第 K 大，或者值域上的复杂查询）。
- **DFS 序 + 莫队/树状数组**: 适合可以将子树问题转化为区间问题的场景。

### 四、 顶尖选手的编码流描述

脑中有了解法，如何行云流水地写出代码？

**Phase 1: 框架搭建与 helper 定义**

- **心态：** 先别管 DSU 的逻辑，先把怎么“动态维护答案”这个核心微操写好。
- **动作：**
  - 定义全局 `cntA`, `cntB`, `cur_S` (当前匹配数), `cnt0_A`, `cnt0_B`。
  - **关键：** 编写 `update(val, type, delta)` 函数。
  - *思考：* 不要手动在循环里写 `if`，封装成函数！
  - `update` 逻辑：先从 `cur_S` 减去旧的 `min`，更新 `cnt`，再把新的 `min` 加回 `cur_S`。处理 $0$ 的特判。

- `cnta[] cntb[] sum`
