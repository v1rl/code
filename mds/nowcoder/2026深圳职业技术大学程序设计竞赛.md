## B 逆向视角下的垂直链摊还维护

**题目极简总结**

**题意**：给定一棵 $n$ 个节点的有根树（根为 1），节点权值是 $0 \sim n-1$ 的一个排列。

**目标**：对于每个节点 $u$，求出在其子树中找一个节点 $v$，使得向下路径 $u \to v$ 上的权值集合的 $\operatorname{MEX}$（未出现的最小非负整数）最大，求这个最大值。

**思路 Trick (Key Observations)**

这是一道标准的“求 MEX 必须正难则反”的刻板印象题，核心跳跃如下：

1. **绝对锚点定位**
   - **跳跃**：MEX 的短板效应决定了，要让 $\operatorname{MEX} \ge 1$，路径**必须**包含权值为 0 的节点 $pos[0]$。
   - **结论**：因为只能找向下的路径，所以只有 $pos[0]$ 的祖先节点才有可能得到 $\operatorname{MEX} \ge 1$。其余所有节点的答案直接是 0。
2. **垂直链法则 (Vertical Chain)**
   - **跳跃**：要达到 $\operatorname{MEX} \ge k$，向下路径必须同时穿过 $pos[0], pos[1], \dots, pos[k-1]$。因为路径是严格向下的，所以这些必需节点**绝对不能位于不同的分支上**，必须形成一条穿糖葫芦般的“垂直链”。
   - **结论**：我们不需要维护整条路径，只需要维护这条必经链的**最高点 $H$** 和**最低点 $L$** 即可。
3. **分情况讨论与链条断裂**
   - 考察下一个数字 $P = pos[k]$ 能否加入链：
     - **向上延伸**：$P$ 是 $H$ 的祖先，此时原本在 $H$ 下方的祖先再也无法包含 $P$，它们的答案定格为 $k$。链最高点上移。
     - **向下延伸**：$P$ 是 $L$ 的子孙，链最低点下移。
     - **已被包含**：$P$ 夹在 $H$ 和 $L$ 之间，无事发生。
     - **彻底断裂**：$P$ 不在垂直链上（在旁支），说明无法再凑出包含 $k$ 的链，剩余祖先的上限全部锁死为 $k$，算法直接终止。

**编码 Trick (Coding Elegance)**

你在这份代码中展现了极其优秀的两个代码习惯，大幅降低了树上操作的常数和代码量：

1. **DFS 序 $O(1)$ 判定祖先后代关系**

   ```cpp
   auto isParent = [&](int x, int y) {
       return in[x] <= in[y] && out[x] >= out[y];
   };
   ```

   遇到“判断 $x$ 是否在 $y$ 上方”的需求，坚决不写 LCA 树上倍增，直接用 DFS 进出时间戳（`in` 和 `out`）进行 $O(1)$ 判定。这是树上问题的高阶素养。

2. **单向游标与摊还分析 (Amortized Analysis)**

   ```cpp
   while(H != P) {
       ans[H] = i;
       H = fa[H];
   }
   ```

   初看这是一个嵌套在 `for` 循环里的 `while` 爬树，很容易让人误以为是 $O(N^2)$。但由于游标 $H$ **只会单调向上移动，且永远不会回退**，所以整个程序运行期间，$H$ 最多只会移动 $N$ 次。这种利用摊还分析将全局赋值均摊为 $O(N)$ 的写法，极其优雅。

**逻辑链条 (The Logic Chain)**

1. **预处理**：记录每个权值对应的节点编号 $pos[x]$；DFS 预处理每个节点的进出时间戳 `in`, `out` 和父节点 `fa`。
2. **定底座**：令垂直必经链的最高点 $H$ 和最低点 $L$ 初始均为 $pos[0]$。
3. **增量验证**：从小到大枚举缺失值 $k = 1 \dots n-1$，考察 $P = pos[k]$ 的位置。
4. **结算出局者**：如果 $P$ 在 $H$ 上方，说明从 $H$ 爬到 $P$ 的这部分节点无法包含 $P$，将它们的答案结算为 $k$，更新 $H = P$。
5. **延伸或断裂**：如果 $P$ 在 $L$ 下方，更新 $L = P$；如果 $P$ 在其他分支导致链断裂，结算当前 $H$ 到根节点的所有答案为 $k$，跳出循环。
6. **最终收尾**：如果循环自然结束（全部数字都能在链上），将剩余未结算的 $H$ 及其祖先的答案赋为最大值 $n$。

## H 括号序列的树形映射与同构排列计数

### 题目极简总结

**题意**：给定一个长度为 $n$ 的合法括号序列（RBS）。你可以执行任意次操作：选择一个局部的 RBS 子串，将其整体翻转，并将 `(` 变成 `)`，`)` 变成 `(`。

**目标**：求通过无限次操作，一共能生成多少种**不同**的合法括号序列（对 998244353 取模）。

**思路 Trick (Key Observations)**

这道题是典型的“操作语义转化”神题。在字符串视角下，翻转加取反的操作极度混乱且难以统计。破局的核心在于**视角的降维**：

- **降维映射（String to Tree）**：任何一个合法的括号序列都可以无损地映射为一棵有根有序树。一对 `()` 代表一个节点，其内部包含的序列代表它的子节点。

- **操作的物理等价（核心跳跃）**：在树的视角下，选中一段局部的 RBS 并翻转取反，**完美等价于在树结构上，将选中的这一段连续的“兄弟节点”的顺序逆转**。

- **可达性分析（冒泡排序思想）**：既然我们可以逆转任意一段连续兄弟节点的顺序，这就等同于我们可以对这些兄弟节点进行任意的相邻交换。因此，我们可以生成这些兄弟节点的**任意全排列**！

- **组合数学转化**：原问题瞬间转化为：在一棵无根树上，允许任意打乱所有节点的子节点顺序，能生成多少种不同的有序树？答案即为每个节点“多重集全排列”的乘积：

  $$\frac{k!}{c_1! c_2! \dots c_m!}$$

  （其中 $k$ 为子节点总数，$c_i$ 为第 $i$ 种同构子树的数量）。

**编码 Trick (Coding Elegance)**

对比你的两份代码，代码二完美展示了 ICPC 竞赛中“大道至简”的防呆编码哲学：

- **五行标准建树法 (Parent-Pointer Parse)**：

  遇到 `(` 就创建新节点并下沉（`u = idx`），遇到 `)` 就闭合当前层并向上回退（`u = fa[u]`）。抛弃了代码一中复杂的栈维护和路径压缩，原汁原味地还原了嵌套层次，零思维负担，绝对不会写错。

- **AHU 思想的精确树同构 (Exact Tree Isomorphism)**：

  代码一使用了加法哈希 `sum += hash[y]`，这在现代赛场上极易被出题人针对（Subset Sum 碰撞）。代码二直接利用 `map<vector<int>, int>`，将排好序的子节点 ID 数组作为该树的“绝对 DNA”。只要 DNA 没见过就分配新 ID，彻底告别随机数，实现了 $100\%$ 零碰撞的精确同构判定。

**逻辑链条 (The Logic Chain)**

1. **结构转化**：将合法括号序列映射为有根多叉树（左括号建子树，右括号退父节点）。
2. **语义翻译**：将“翻转并取反子串”等效翻译为“任意重排同层兄弟节点的顺序”。
3. **目标确立**：问题转化为求树的自同构排列数，即按层累乘 $k! / \prod(c_i!)$。
4. **同构判定**：自底向上遍历，收集子节点 ID 并排序，利用 Map 为每种独特的子树结构分配全局唯一 ID。
5. **组合累乘**：在递归回溯的过程中，利用同构计数 $c_i$ 计算当前层的有效排列数，累乘至最终答案。
