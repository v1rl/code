## B **周期分块同余与字典序贪心代数降维**

------

**一句话题意**

机器人从 $(0, 0)$ 出发，指令 `0` 向右走（横坐标 $+1$），指令 `1` 向上走（纵坐标 $+1$）。给定一个包含 `0`, `1`, `2` 的长度为 $n$ 的字符串 $s$。你需要将所有的 `2` 统一替换为 `0` 或 `1`，使得机器人不断**循环执行**该指令串时，能够恰好到达目标点 $(x, y)$。求字典序最小的替换方案，若无解输出 -1。

（数据范围：$n \le 10^5$，$x, y \le 10^{18}$）

------

**思路 Trick：关键思维跳跃**

在 ICPC 中，遇到“无限循环执行”并求到达某点的判定，如果直接按周期去模拟坐标变化，很容易陷入繁琐的取模运算和边界分类。本题的核心跃迁在于**将物理移动的无限流，彻底坍缩为有限变量的线性不定方程**：

1. **绝对步数的截断坍缩（物理转代数）**

   - **痛点**：无限循环的字符串看起来没有尽头，不知道要在哪里停下。
   - **跳跃点**：由于所有的操作（无论是 `0` 还是 `1`）都会让横坐标或纵坐标严格增加 1，所以要走到 $(x, y)$，**机器人走过的总步数被死死地焊死在了 $x + y$ 步**！
   - 这意味着，我们根本不需要关心无限循环，我们只需要截取无限指令流的前 $x + y$ 个字符。只要这前 $x + y$ 个字符里恰好有 $x$ 个 `0`（剩下的自然是 $y$ 个 `1`），目标就必然达成！

2. **左右半块的频次降维（状态压缩）**

   - 前 $x + y$ 个字符，必然由 `times = (x + y) / n` 个完整的 $s$ 串，加上一个长度为 `mid = (x + y) % n` 的前缀拼凑而成。

   - **跳跃点**：原串 $s$ 被天然切成两块：左半块（前 `mid` 个字符）在最终执行流里出现了 `times + 1` 次；右半块（剩余字符）出现了 `times` 次。

   - 我们不需要关心具体的 `2` 在哪里，只需设左半块有 $l_0$ 个 `2` 变成了 `0`，右半块有 $r_0$ 个 `2` 变成了 `0`。这就把一个长达 $10^5$ 的字符串匹配，降维成了一个极其纯粹的二元一次方程：

     $$(times + 1) \times (\text{左半块初始0的数量} + l_0) + times \times (\text{右半块初始0的数量} + r_0) = x$$

3. **字典序的单调性枚举（贪心收敛）**

   - 要求替换后的 $s$ 字典序最小，核心原则有两个：
     1. 左半块（靠前的字符）要尽可能多地填 `0`。
     2. 确立配额后，`0` 要尽可能填在靠前的位置。
   - 因此，直接 `for(int i = numL[2]; i >= 0; i--)` 从大到小暴力枚举 $l_0$。一旦算出的 $r_0$ 是整数且在合法范围内，这就**绝对是字典序最小的最优解**，直接 `break`！

------

**编码 Trick：优雅实现范式**

1. **基于配额池的无状态贪心输出**

   ```cpp
   if(s[i] == '2') {
       if(l0) { cout << 0; l0 --; } 
       else { cout << 1; }
   }
   ```

   解出最优的 $(l_0, r_0)$ 后，你没有去使用额外的数据结构记录要把哪些下标改成 `0`。而是直接把 $l_0$ 作为一个“配额池”。从头遍历左半块，遇到 `2` 时，只要池子里还有配额就填 `0`，没有了就填 `1`。这种天然利用从左到右遍历顺序的贪心，完美契合了“字典序最小”的要求，同时让代码极其轻量级。

------

### 解决本题思路的逻辑链条

1. **绝对步数定界**：确立机器人走到终点的总步数必须为 $x + y$，从而将原问题转化为截取前 $x + y$ 个指令的问题。
2. **周期分块**：计算 $x + y$ 包含完整周期数 `times` 以及余数 `mid`，将原串物理分割为左半块与右半块。
3. **特判除零**：拦截 `times == 0` 的情况，直接在左半块分配必需的 `0`，并将不影响结果的右半块全部贪心填 `0`。
4. **方程枚举**：建立 $0$ 的总需求量关于 $l_0$ 和 $r_0$ 的二元一次方程。从大到小枚举左半块的转化量 $l_0$ 以保证字典序最优，利用 $O(1)$ 数学反解并校验 $r_0$。
5. **配额贪心**：将合法的 $(l_0, r_0)$ 转化为配额，分块顺序遍历原串，遇 `2` 优先消耗 `0` 配额，边扫描边输出，完成最终构造。
