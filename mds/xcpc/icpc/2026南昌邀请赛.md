## **C【广义矩阵快速幂】求定长最小瓶颈路**

**极简题意总结**

给定一张包含 $n$ 个点的有向图。

初始有 $m$ 条权值为 0 的边。随后 $k$ 天，每天新增一条权值为 $i$（天数）的有向边。

有 $q$ 次询问，每次求：从起点 $s$ 到终点 $t$ 走**恰好 $w$ 步**，所有合法路径中，**最大边权的最小值**是多少（若不可达输出 -1）。

**题目核心 Trick (思维跳跃点)**

1. **业务逻辑到图论的映射 (Time $\to$ Edge Weight)：**

   题目描述的“等路修好”，本质是路径上**最晚修好的那条边**决定了整条路可用的时间。这是一个跳跃：将“最早出发时间”转化为求一条路径，使得路径上的**最大边权（瓶颈）尽可能小**。这就把业务题变成了经典的“最小瓶颈路”模型。

2. **“恰好 $w$ 步”的条件反射 (定长路径 $\to$ 矩阵快速幂)：**

   在图论中，一旦看到“恰好走 $w$ 步”，并且 $n$ 很小（200 以内）、$w$ 很大（$10^9$ 级别），应该形成条件反射：**邻接矩阵的幂运算**。

3. **乘法运算符的重定义 (广义矩阵乘法)：**

   最难的跳跃在于发现常规矩阵乘法 $C_{i,j} = \sum(A_{i,k} \times B_{k,j})$ 和最短路矩阵乘法（Floyd） $C_{i,j} = \min(A_{i,k} + B_{k,j})$ 都可以被推广。

   为了求最小瓶颈路，我们将内层运算换成 $\max$（求两段路径合并后的瓶颈），外层运算换成 $\min$（在所有中转方案中取最优）。

   即：$C_{i,j} = \min_{k} \{\max(A_{i,k}, B_{k,j})\}$。只要该定义满足**结合律**，就可以直接套用快速幂。

**编码 Trick (优雅习惯)**

从你的 AC 代码中可以看出你的基础非常扎实，这里总结代码中的几个极佳的编码习惯（也是很多高水平选手常用的 Trick）：

1. **规避广义单位矩阵 (`fst` 标志位法)：**

   在普通的乘法快速幂中，我们会初始化 `res` 为单位矩阵（主对角线为 1，其余为 0）。但在 $\min-\max$ 这种广义代数系统中，推导单位矩阵（主对角线为 0，其余为 `inf`）有时会让人犹豫甚至出错。

   **你的 Trick：** 在 `qmi` 函数中使用 `bool fst = false;` 标志位。在二进制第一次遇到 1 时，直接赋值 `res = A`，后续再做乘法。这是一种**极其通用且鲁棒**的写法，无论算子怎么重定义，都不需要去想“单位元”是什么。

2. **Cache 友好的循环顺序与常数优化 (`i-k-j` 与剪枝)：**

   在 `operator*` 中，你使用了 `i -> k -> j` 的循环顺序，而非教科书上的 `i -> j -> k`。这使得内层循环访问 `B.mat[k][j]` 和 `C.mat[i][j]` 时内存地址是连续的，极大提高了 CPU Cache 命中率。

   结合 `if(A.mat[i][k] == inf) continue;` 的剪枝，直接将常数时间削减了大半。这在 $O(n^3 \log w)$ 的复杂度下，是能否 AC 的关键。

3. **多重边的天然过滤 (`min` 覆盖)：**

   题目中提到可能会“在已经有的地方建路”，即存在重边。在读入后续边时，直接 `A.mat[x][y] = min(A.mat[x][y], i)`，用局部最优的贪心策略在建图阶段就过滤掉了无用边，避免了图结构的冗余。

**逻辑链条 (一步一总结)**

1. **提取核心需求** $\to$ 需要找定长 $w$ 的路径。
2. **抽象边权定义** $\to$ 边权即为建成的天数（0 到 $k$）。
3. **转化路径代价** $\to$ 路径可用时间 = 路径上所有边权的最大值。
4. **确立最终目标** $\to$ 在所有长为 $w$ 的路径中，最小化这个最大值（最小瓶颈路）。
5. **匹配数据结构** $\to$ $w$ 极大，$n$ 较小，必须依靠邻接矩阵快速幂加速状态转移。
6. **推演状态转移** $\to$ 重定义矩阵乘法 $C_{i,j} = \min(\max(A_{i,k}, B_{k,j}))$。
7. **全局预处理** $\to$ 用 $O(n^3 \log w)$ 求出 $A^w$ 矩阵。
8. **回答独立查询** $\to$ 查询结果即为矩阵元素 $R_{s,t}$，实现 $O(1)$ 响应。



## **D【状压换根 DP】内外解耦与补集转化**

**极简题意总结**

给定一棵 $n$ 个节点的树，每个点带有一个物品集合（种类总数 $m \le 6$）。

我们可以任意修改**叶子节点**上的物品集合。

求：依次以 $1 \dots n$ 为根节点时，最少需要修改多少个叶子节点，才能使得**从根到所有叶子节点的路径上，物品的并集完全相同**。

**题目核心 Trick (思维跳跃点)**

1. **正难则反与贪心 (补集转化)：**

   要求“最少的修改次数”，正面考虑如何修改非常困难。跳跃点在于：**最少修改数 = 树的叶子总数 - 最多可以不修改的叶子数**。我们只需要枚举所有可能的目标集合 $S$，看在当前根下，有多少条路径原本的并集刚好就是 $S$。

2. **识别“必然集” (约束发现)：**

   我们要统一所有路径的集合，但**非叶子节点是无法修改的**。这意味着，整棵树中所有度数 $\ge 2$ 的节点（内部节点），它们的物品一定会出现在所有的路径中。因此，不管以谁为根，最终的目标集合 $S$ **必须包含所有内部节点的物品并集**（代码中的 `base`）。同时，当前根节点显然也不能修改，所以 $S$ 还必须包含 `mask[root]`。

3. **换根 DP 的状态拆分 (内外正交)：**

   既然 $m \le 6$，状态空间极小（最多 64 种）。我们可以用频率数组统计各种并集出现的次数。

   定义 `inpath[x][s]` 为 $x$ 子树内走向叶子的路径数；`outpath[x][s]` 为从 $x$ 往上走（子树外）通向叶子的路径数。这就构成了经典的换根模型。

**深度解析：为什么换根 DP 外部`out`的状态通常不包含 `x` 本身？**

在树形结构中，我们喜欢把状态定义为“极其纯粹的组件”。

- 一般来说，我们会让换根DP内部`in`的状态包含`x`本身，此时如果外部的`out`状态也包含`x`本身，`x`就被计算了两次，不符题意。此时会考虑外部不计算`x`本身，但要考虑特判根节点度数为`1`

- **乐高拼装思维：** 我们希望把节点 $x$ 看作一个连接器，它的子树 $y_1, y2 \dots$ 是向下的模块，它的父节点方向是向上的模块 `out`。

  当我们要算以 $y_1$ 为视角的外部时，只需要把“纯粹的 `out`” + “$x$ 本身的信息” + “兄弟 $y_2 \dots$ 的 `inpath`” 组合起来即可。**不包含 $x$ 的 `out` 是一个完全独立的拓扑块**，使得转移方程更加干净、普适。

**编码 Trick (优雅习惯)**

从你的 AC 代码中，可以看出你在树形 DP 上的编码习惯非常好，这里总结两个极大降低思维复杂度的编码 Trick：

1. **定长数组代替 Vector (`array<int, 64>`)：**

   在状态维数已知且很小（这里是 $2^6 = 64$）时，使用 `std::array` 而不是 `std::vector`。这不仅避免了堆内存分配的开销，且内存连续，对 CPU Cache 极其友好，常数极小。

2. **利用频率加减，规避繁琐的“前后缀合并” (`cnt` 数组的妙用)：**

   在处理换根 DP 时，节点 $x$ 把状态传给儿子 $y$ 时，往往需要“除了 $y$ 以外所有儿子的信息”。很多题解会使用冗长的前缀数组和后缀数组来合并。

   **你的 Trick：** 因为我们记录的是“出现某种集合 $s$ 的**次数**”，而次数的加减法是**可逆**的！所以你直接把 `outpath[x]` 和所有儿子的 `inpath` 暴力加进 `cnt[s]` 中（代表完整的全集）。在传给 $y$ 时，直接 `cnt[s] - inpath[y][s]` 就得到了除去 $y$ 以外的其他所有路径。这把原本需要几十行、容易写错的前后缀逻辑，压缩到了几行干净的加减法中。

**逻辑链条 (一步一总结)**

1. **状态压缩预处理** $\to$ 将每个节点的物品种类转化为二进制整数 `mask`。
2. **提取全局限制** $\to$ 扫描全树，找出所有度数 $\ge 2$ 的内部节点，求出它们的掩码并集 `base`。
3. **自底向上 (第一遍 DFS)** $\to$ 求出 `inpath[x][s]`，即 $x$ 子树内以集合 $s$ 到达叶子的路径数。
4. **自顶向下 (第二遍 DFS)** $\to$ 求出 `outpath[x][s]`，利用 `cnt` 总和减去当前子树贡献，计算向外的路径数。
5. **根节点统计** $\to$ 枚举每一个节点 $x$ 作为根，计算出从 $x$ 出发所有方向的路径总频率。
6. **合法性过滤与求最值** $\to$ 对于合法的目标集合 $S$（需满足包含 `base` 且包含 `mask[x]`），找出命中次数最多的路径数 $mx$。
7. **计算最终答案** $\to$ 输出 总路径数 - $mx$。
